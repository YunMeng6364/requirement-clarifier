# 输入适配、拓扑与细节

| 输入类别 | 提取方法 | 边界 |
|---|---|---|
| 描述、Markdown、普通文档 | 从标题、列表、表格抽取对象、层级、关系和条件，保留关键术语。 | 不把泛泛主题补成实际产品能力；示范知识标为假设／演示。 |
| JSON／YAML／配置／依赖清单 | 读取键、层次、服务和显式依赖，区分结构包含与运行关系。 | 嵌套不自动表示业务分层，变量不自动成为模块，不在图中暴露凭证值。 |
| 源码、API、数据库、CI／基础设施 | 提取显式实体、边界、调用／约束／外键／阶段，必要时结合注释核实。 | import 不自动等于运行调用；缺失条件标未知，材料冲突在提纲中说明。 |
| CSV／TSV／表格 | 识别列与行的实际语义，再决定节点和关系。 | 不默认“一行一条关系”；数量和比例须有数据依据。 |
| PDF、Office、图片或既有图 | 用当前环境已有的读取／提取工具获得内容，既有 SVG 读源码，矢量图保留可编辑文字语义。 | 不要求用户先重排格式；缺提取工具、扫描识别不足或读取权限受阻就说明影响，不假装读过、不自动安装、不把整图图片嵌入新 SVG。 |
| 未列格式 | 先识别文本／二进制及已有可用工具，再提取可核实结构。 | “任意格式接收”不等于“任何环境必能解析”；确实歧义才逐问，环境缺工具归环境受阻。 |

| 主拓扑 | 适用内容 | SVG 实施起点与限制 |
|---|---|---|
| `nested` | 真实包含、分层包裹 | `layers.svg` 的容器与卡片显式重排；包含不用执行箭头替代。 |
| `left-to-right` | 有方向的顺序、分支与反馈 | `flow.svg`；预留回路通道，不能靠横向无限画布或持续缩字号。 |
| `hub-and-spoke` | 一个中心连接多个外围 | 复用 `flow.svg` 卡片、marker、symbol，计算静态坐标；不迁移 DOM／JS 动画。 |
| `timeline` | 有序竖向步骤或事件 | 从 `flow.svg` 改成纵向；时间未知就只列顺序，不捏造日期／时长。 |
| `grid` | 同维度矩阵、功能／能力对照 | `layers.svg` 的网格；保持行列标题与维度。 |
| `tree` | 父子层级、组织、分类、决策分叉 | 复用 `layers.svg` 卡片和 `flow.svg` 连接组件；按真实父子／分支摆放。 |
| `funnel` | 逐步过滤／收窄 | 从 `flow.svg` 重排梯形／阶段；宽度若无数量依据须图注“示意，非定量比例”。 |
| `comparison` | 2–3 方案同维度并列 | `layers.svg` 网格或 `overview-detail.svg` 分区；不擅自加推荐结论。 |

每张 SVG 恰有一个主拓扑；局部机制可作为子结构，不能强迫复杂业务只剩一串箭头。总览＋详图选择 `overview-detail.svg`；它是展示组合，不是第九种拓扑，分别声明各图／主区域的主拓扑。模板只是几何和视觉起点，不能复制示例业务文字当内容；八拓扑不要求八个新模板，也不承诺通用自动布局算法。

细节：`high-level` 展示主要实体、名称及必要作用，不放普通元数据；关键条件、边界和假设不因高层而删除。`medium` 为默认：所需实体、每节点 1–2 项已核实信息及必要关系标签。`detailed` 展示已提供／可核实的子组件、配置、说明与状态，缺数据仍标未知，不靠等级补造信息。按用户明确要求优先，其次按受众／用途，未指定采用 `medium`。聚合／省略只能在确认前提出并获批；冻结后以扩区域、重排或预先批准的拆图方案解决密度。
