# 使用示例

自然语言或 `$editable-diagram-svg` 调用；提供材料、用途、尺寸即可，图名未指定时给建议。默认中文、单页16:9、medium细节。输入不需手工重排；未知或不可读范围明确说明。

> 用 $editable-diagram-svg 将这份 YAML 服务清单画成可编辑SVG。先提取真实服务与显式依赖，一份提纲里建议主拓扑、细节、精确色值与展示尺寸，我一次确认后生成并实际渲染检查。

> 用 $editable-diagram-svg 做虚构的资料审核流程：提交→自动检查→人工审核→发布，两个失败都退回修改，修改后重新提交。审核链可以蓝、发布青绿；只从预设色板取值，不画材料外的存储或通知。先确认整份提纲。

> 用 $editable-diagram-svg 修改这张已经确认的SVG。只将“发布”改为“预约发布”，新增“时间已到／未到”分支。给我新增内容与关系的差异提纲，其他已批准内容保持原样。

> 用 $editable-diagram-svg 只改这张SVG的颜色；将指定分组改成白名单纯紫 `#5b6cff`。先列出旧→新精确映射与预期次数，保留文字、几何、结构和线型，不新增图例或装饰，断言失败不部分写入。

## 单次确认

正常顺序：材料→内容／拓扑／细节／配色／尺寸／装饰与拆图提纲→一次批准→`acceptance.json`冻结→生成→结构／冻结／色板→实际渲染目视→SVG与四类检查结果。具体内容与布局已批准就沿用，不重复询问。只有真正歧义才逐问；批准后新增可见元素或更改被冻结内容，先说明具体差异再增量确认。

包内 `examples/` 与 `verification/forward-test/` 全部为演示，确认状态为 simulated，只能加 `--example-mode` 演练；不能假装真实用户批准。旧兼容词表检查也不代替完整acceptance。

## 参数调整

| 需求 | 表达 |
|---|---|
| 拓扑 | “采用包含层级”“主顺序优先，反馈有独立回路”“比较三方案” |
| 细节 | “高层实体”“medium且每节点1–2项信息”“已有数据的详细机制” |
| 尺寸 | “1600宽显示，viewBox1920×1080”“纵向滚读”“总览和详图拆成SVG” |
| 视觉 | “同组稳定颜色”“蓝灰用于这个辅助组，不按职责定色”“图标只用已列动作” |
| 边界 | “这些名称／条件已确认”“计划与事实分开”“未知标明，不补模块” |

修改比例不只是改width／height；要重新安排文字、通道、密度，若超出冻结尺寸先确认差异。像素导出更多可保留viewBox，不意味展示可读性已验证。最终只给SVG源文件，预览看过后清理；字体回退会改字宽与换行，接收机器未验需写未执行。
